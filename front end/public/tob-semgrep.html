Overview

What it does

Given a source tree and target languages, the tob-semgrep skill runs Semgrep static analysis with automatic language detection, parallel Task execution, and merged SARIF output. It is the primary execution framework the Static Analysis Skill reaches for, driving ruleset selection, parallel scan Tasks, and result merging end to end.

Its guiding principle: third-party rulesets are required, not optional — Trail of Bits, 0xdea, and Decurity rules catch vulnerabilities absent from the official Semgrep registry. Every command runs with --metrics=off, and the ruleset plan requires explicit user approval — a hard gate — before any scan executes.

Mechanics

How it works

The 5-step scan workflow, invoked by the Static Analysis Skill.

01

Resolve output & detect languages

Auto-increments the output directory, creates raw/ and results/, globs for language counts.

02

Select scan mode & rulesets

Run-all or important-only, pre- and post-filtered by category, confidence, and impact.

03

Present plan — hard gate

Shows exact rulesets, targets, engine, and mode; proceeds only after explicit approval.

04

Spawn parallel scan Tasks

All Tasks emitted in one message with absolute paths and --metrics=off.

05

Merge results & report

Merges SARIF, applies post-filter, and calls out what Semgrep missed.

Quality

Evaluation criteria

The bar a scan run must clear before it is trusted.

✓  --metrics=off present on every Semgrep command.
✓  Plan approved via AskUserQuestion before any scan Task is spawned.
✓  Required third-party rulesets included alongside the official registry.
✓  All scan Tasks emitted in parallel, in a single message.
✓  Coverage gaps explicitly called out, not silently omitted.
