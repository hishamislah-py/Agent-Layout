Overview

What it does

Given a system design or architecture, the Threat Modeling skill identifies and analyzes threats against it, applying STRIDE, PASTA, and attack tree methodologies to map assets, trust boundaries, data flows, and threat actors. It runs upstream of both the API Security Skill and the Static Analysis Skill, defining which components to test and which threat categories carry the highest risk for the system.

Its guiding principle: identify what could go wrong before building a test plan — threats found at design time cost far less to fix than those found in production. The output is a prioritized risk register that feeds the API Security Skill with a ranked attack surface map, so the most critical endpoints are tested first.

Quality

Evaluation criteria

The bar a threat model must clear before it is trusted.

✓  Every asset and trust boundary identified before threat enumeration begins.
✓  STRIDE applied per component, not just at a system-wide level.
✓  Every threat scored with DREAD for prioritization.
✓  Risk register connects technical findings to business impact.
✓  Trust boundary violations surfaced even when no scanner would catch them.
