Overview

What it does

Point it at a legacy codebase and the Discovery Agent works through it one file at a time, producing a structured inventory entry for the Migration Knowledge Base. It separates real domain logic — validations, calculations, decisions, workflows — from framework plumbing like logging and error handling.

Its governing rule is restraint: extract only what is actually in the code. Where the code is unclear, it never quietly guesses — it records the ambiguity, its best interpretation, and exactly what input from a subject-matter expert would resolve it.

Capabilities

What it extracts from every file

/ inventory

Code inventory

Every function, class, and method — with line ranges, a one-line purpose, and a complexity estimate.

/ business_rules

Business-rule extraction

Domain logic captured as plain-English rules with traceable IDs, pseudocode, inputs, outputs, and edge cases.

/ dependencies

Dependency mapping

Classifies internal, external, infrastructure, and library dependencies and how each is used.

/ data_structures

Data-structure analysis

Captures fields and the relationships between the structures a file defines or touches.

/ complexity · dead_code

Risk flagging

Surfaces complexity hotspots and suspected dead code with severity ratings and supporting evidence.

/ ambiguities

Ambiguity detection

Documents each uncertainty with a best-guess reading and the exact SME input needed to resolve it.

Mechanics

How it works

A single file passes through five steps, from raw source to a validated knowledge-base entry.

01

Language detection

Infers the language from the file extension — Python, JS/TS, Java, C#, Go, Ruby, SQL, YAML, JSON, XML, Bash, TOML.

02

Adaptive model selection

Routes high-complexity files to a stronger model tier and standard files to the default, balancing depth against cost and speed.

03

Smart truncation

Caps very large files at 800 lines to stay within prompt limits without timing out, noting what was trimmed.

04

Context-aware prompting

Includes the application, module, and summaries of related already-analyzed files so findings stay coherent across the codebase.

05

Structured output

Returns strict JSON validated into a discovery record. Unparseable responses degrade to a flagged, zero-confidence entry — never a crash.

Each file produces one structured record, written into the Migration Knowledge Base.

dead_codeSuspected unused code with evidence and confidence.
ambiguitiesEach with a best interpretation and the SME input that resolves it.
overall_confidenceA 0–1 score for the whole file's analysis.
Quality gate — entries scoring below 0.60 are flagged for SME review before the pipeline advances.

Operating principles

The rules it works by

No hallucination

Extract only what is present in the code. Nothing is invented to fill a gap.

Business vs. technical

Logic a stakeholder would recognize is kept separate from framework plumbing.

Surface every ambiguity

Uncertainty is documented explicitly and routed for resolution — never resolved silently.
