Overview

What it does

Given a requirement document — BRD, FRD, PRD, spec, user stories, or epics — the BRD / FRD Analyzer skill classifies the document type, extracts and catalogs every requirement, and flags ambiguity, gaps, and risk before any test is written. It is the capability that runs upstream of the QA Automation Agent, turning raw requirement docs into clear, testable requirements ready to become specs.

Its guiding principle: what isn't written matters as much as what is — if you can't write a test for it, it isn't a requirement. Every requirement is checked for measurable, unambiguous, testable, atomic, and feasible; untestable items are surfaced with the exact clarifying questions to take back to the BA or PO.

Quality

Evaluation criteria

The bar a catalogued requirement must clear before it is trusted.

✓  Document correctly classified before extraction begins.
✓  Every requirement assigned an ID, actor, and acceptance criteria.
✓  Measurable, unambiguous, testable, atomic, feasible — checked per item.
✓  Gaps, risks, and dependencies made explicit, not implied.
✓  No untestable item passed downstream without a clarifying question.
